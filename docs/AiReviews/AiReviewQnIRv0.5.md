# HIGH LEVEL SUMMARY
---
## Summary
This consolidated technical dossier and adversarial review proposal presents the unified specification of the Qn computational universe alongside the QnIR v0.3 (`v0.3.0-draft.30`) deterministic intermediate representation through Step 5 closure. It synthesizes the SIMEMP (v1.4.0) and Best of Choices (BOC v0.4.1) constitutional governance layer, the four-layer execution core and two-axis $Q(\text{reuse})$ admission primitives, orthogonal domain projections (`Qm`, `Qs`, `Qlog`, `Qphy`, `Qchem`, `Qbio`), and the 16-opcode QnIR minimal core, while surfacing post-`draft.18` delta evolutions, cross-file discrepancies, and dependency ordering questions required before opening Step 6 or attempting QnIR promotion.

## Strengths
* **Integrated Deterministic IR and Verifiable Accounting Architecture:** The QnIR v0.3 core unifies floating-point-free exact arithmetic, canonical minimal-zoom normalization, basic-block arguments with finite back-edge trip ceilings, a four-identity work escrow ledger, and deterministic CBOR (`qir-enc-1`) binary Merkle trace roots (`qir-trace-root-1`) paired with dual Rust and Python golden-first differential conformance implementations.
* **Consensus-Safe Two-Axis Memory Admission and Latency Harvesting:** The SIMEMP and `qnPrimitive` specifications introduce a consequentiality constraint that gates lookup optimizations ($Q(\text{reuse})$) on static worst-case advantages across both logical work ($\kappa_{\text{dcc}}$) and per-tier memory latency ($\kappa_t$), paired with a strict "Never-Feeds-Back" rule and a deterministic Memory Wall Latency Harvester that prevent hardware timing variance from contaminating state determinism ($H(S_t \mid \mathcal{D}(S_t)) = 0$).
* **Auditable Multi-Stage Candidate Adjudication Protocol (BOC):** The BOC v0.4.1 profile replaces opaque scalarized compiler heuristics with a deterministic two-stage state machine—combining a Tier-1 existential invariant filter with Tier-2 lexicographic minimization over implicit dependencies, worst-case logical work, external coupling, and target profile gaps—that preserves explicit evidence-modality typing and emits domain-separated cryptographic decision receipts.

## Weaknesses
* **Syntactic vs. Semantic Scope of the Exact Admission Surrogate Equality Claim ($\hat{B}(P) = B(P)$):** Please consider clarifying in `qnir_accounting.md` §3.4 that retiring the depth ceiling (`F26`) establishes exact equality between the topological DP surrogate $\hat{B}(P)$ and the *syntactic trip-unrolled control-flow graph supremum* $B_{\text{cfg}}(P)$ (and requires a pre-dispatch state-count cap to prevent Cartesian trip-product blowup), whereas $\hat{B}(P) \ge B_{\text{sem}}(P) = \sup_D \text{Work}(\text{Eval}(P, D, V))$ remains a conservative upper bound over semantically feasible executions due to path-insensitive `BR` conditions, correlated `CLOAD` outcomes, and early `0 U` rejection transitions.
* **Cross-Layer Accounting and Lowering Gaps Between SIMEMP/$Q(\text{reuse})$ and the QnIR Core:** The authors might consider reconciling the constitutional pre-inspection gateway fee ($W_{\text{gate}} > 0$) and the four-field two-axis $Q(\text{reuse})$ Admission Ledger with QnIR's zero-posting admission refusals (`Work(E) = 0 U` on `X2`/`X50`), mid-trace refund prohibition (`F13`), and flat single-table `CLOAD` instruction by formally separating the outer principal gateway ledger ($\Delta B_{\text{principal}} = W_{\text{gate}} + \text{Work}(E)$) from inner QnIR transition escrow and defining `R11'` as a compile-time `OP_BYPASS` erasure and static two-axis lowering gate.
* **Incomplete Step 5 Golden Registration (`F6`), Unbumped Semantics Version String (`V`), and `P_gap` Harmonization:** Before opening Step 6, it would be helpful to promote the synthetic `F6` collision self-test to a committed CLI fixture in `qnir_goldens.md` and `qnir_conformance.md` §4.4, resolve the `V.semantics` version drift where vectors `X1`–`X51` retain `v0.3.0-draft.5` despite substantive `F25`/`F26` semantic changes in `draft.8.2`/`draft.8.3`, and harmonize active QnIR specifications from `P_coverage` to `P_gap` with a historical invariance attestation for `draft.7`–`draft.30`.
* **Cross-Layer Terminal Status, Quarantine Disposition, and Domain Lowering Ambiguities:** The authors may want to establish a formal projection between Axiom 6's Sealed 12-Status Terminal Registry (as well as unregistered tokens like `HALTED` and `FRAME_SIGNATURE_INSUFFICIENT`, plus the three distinct uses of `QUARANTINED`) and QnIR's 4 closed terminal outcomes, while clarifying how non-dyadic `Qm` zoom schedules (`Decimal`, `Factorial`), `Cons_B` radices, and origin-quotiented commitments ($\hat{Q}(0)$) lower into QnIR.
* **Standards-Alignment Edge Cases in BOC RFC 8785 JCS Serialization and NIST SP 800-90B Onboarding:** Please consider specifying string encoding for >53-bit and arbitrary-precision integer fields in `CDQN-BOC-RECEIPT-v1` receipts so that standard RFC 8785 IEEE-754 `binary64` number canonicalization does not conflict with Operational Axiom 10 (Reference Paper: RFC 8785: JSON Canonicalization Scheme (JCS), Anders Rundgren et al., 2020), and clarifying in `q0_q1.md` §2 that the 4,096-bit boot harvest executes startup health tests (RCT/APT) against an offline-certified $H_{\min} \ge 0.85$ profile rather than full min-entropy estimation from scratch, which requires $\ge 10^6$ samples (Reference Paper: Recommendation for the Entropy Sources Used for Random Bit Generation, Meltem Sönmez Turan et al., 2018).
* **BOC v0.4.1 Edge-Case Rules and Causal Ordering of Step 6 / Standing Governance Queue Workstreams:** The specification would benefit from tightening BOC v0.4.1 rules on Stage-1 three-valued Kleene dominance, Stage-2 `UNKNOWN` poison-pill pruning, and checkpoint budget reservation idempotency, as well as executing the pre-Step-6 baseline seal (`draft.31`), core Layer-0 physical calibration (`QO-17`), and prerequisite Standing Queue items (`Q1`, `Q3`, `Q2`, `Q5`) prior to the topologically ordered Step 6 extension studies (`Containers` $\to$ `Calls` $\to$ `Saturation` $\to$ `Fork–join` $\to$ `Road proofs / AIRs`) and post-promotion triggers (`Q4`, `Q6`).

## Potential Issues And Suggestions
### [Executive Scope, Post-draft.18 Delta Register & Constitutional Governance Layer (SIMEMP v1.4.0 & BOC v0.4.1)] (Pages: 1-11)
#### Potential Mistakes and Improvements

1. **Unverified Edge Cases in the BOC Operational Profile (`boc.md` v0.4.1): Stage-1 Three-Valued Logic, Stage-2 `ImplicitDeps` Tier Placement, Partial-Order Deadlocks, and Checkpoint-Budget Idempotency (§2.1, pp. 7–8; §2.3, pp. 9–11)**
   - **Potential Concerns (Formal Stress-Test of `boc.md` v0.4.1):** Section 1.2.1 (p. 6) notes that `boc.md` v0.4.1 has never been technically stress-tested by Deep Review. Auditing §2.3 (pp. 9–11) against §2.1 (pp. 7–8) reveals four boundary ambiguities requiring tightening:
     1. **Intra- vs. Inter-Candidate Dominance of `UNRESOLVED` in Stage 1 (p. 10):** Stage 1 filters $C_{\text{valid}} = \{c \in C \mid I_{\text{Id}}(c) \wedge I_{\text{Met}}(c) \wedge I_{\text{Sec}}(c) = 1\}$ over states `PASS`, `FAIL`, `UNRESOLVED` (plus `NOT_EVALUATED` on short-circuit after a decisive `FAIL`), and mandates: *"Any decision-affecting `UNRESOLVED` returns `INCONCLUSIVE`, never `NO_ADMISSIBLE_CANDIDATE`."* First, at the *intra-candidate* level, `boc.md` should explicitly mandate strong Kleene three-valued conjunction ($\text{FAIL} \wedge \text{UNRESOLVED} = \text{FAIL}$) so that predicate evaluation order cannot turn a candidate having both a `FAIL` and an `UNRESOLVED` predicate into a decision-affecting `UNRESOLVED`. Second, at the *inter-candidate* level, when $C_{\text{valid}} \neq \emptyset$ (e.g., $c_1 \in C_{\text{valid}}$ achieves all `PASS`) but another candidate $c_2$ yields overall Stage-1 `UNRESOLVED` (zero `FAIL`s, at least one `UNRESOLVED`), $c_2$ might have beaten $c_1$ in Stage 2 had its unresolved predicate evaluated to `PASS`. The specification must state whether any overall-`UNRESOLVED` candidate $c_2$ automatically forces the BOC invocation to return `INCONCLUSIVE` whenever $c_2$'s known Stage-2 prefix is not already strictly dominated by $\min_{c \in C_{\text{valid}}} \text{LexKey}(c)$.
     2. **Constitutional Tension Between the No-Implicit Rule (§2.1, p. 8) and Stage-2 `ImplicitDeps(c)` (§2.3, p. 10):** Section 2.1 defines Dependencies Determinism ($H(S_t \mid \mathcal{D}(S_t)) = 0$) and the **No-Implicit Rule** (*"No implicit entity, behavior, type coercion, default, or convention may cross a SIMEMP Gateway"*) as Tier-1 constitutional invariants. Yet Stage 2—which evaluates only candidates $c \in C_{\text{valid}}$ that have *already passed* Stage-1 hard admission—places $\text{ImplicitDeps}(c) \in \mathbb{N}$ (*"discoverable, attributable dependencies absent from declared commitment"*) as the first minimization component of $\text{LexKey}(c)$. If any candidate with $\text{ImplicitDeps}(c) > 0$ violates Dependencies Determinism and the No-Implicit Rule, it would fail Stage 1, making $\text{ImplicitDeps}(c) \equiv 0$ vacuous in Stage 2. `boc.md` should clarify that $\text{ImplicitDeps}(c) > 0$ is admissible only during *pre-gateway candidate synthesis/repair BOC profiles* (where discoverable dependencies are surfaced for explicit attribution prior to sealing), whereas at any sealed SIMEMP Gateway crossing, $\text{ImplicitDeps}(c) = 0$ is enforced as a hard Stage-1 ($I_{\text{Id}} / I_{\text{Sec}}$) requirement.
     3. **Stage-2 Partial-Order Deadlocks, Poison-Pill `UNKNOWN` Candidates, and Modality Comparability on $\Delta W_{\text{worst}}(c)$ (pp. 10–11):** Each component of $\text{LexKey}(c)$ carries an evidence modality in $\{\text{MEASURED}, \text{FORMALLY\_DERIVED}, \text{QUALITATIVE}, \text{UNKNOWN}\}$, with rules prohibiting *"skipping an incomparable earlier component"* and routing *"Residual full-key ties"* to pre-bound authority $A$. Because incomparable values (`UNKNOWN` or cross-rubric/unmapped `QUALITATIVE`) induce only a partial order over $C_{\text{valid}}$, three edge cases require explicit rules in `boc.md` §8: (i) If candidate $c_1$ has a proven `FORMALLY_DERIVED` bound at component $k$ while $c_2$ has `UNKNOWN` (and they tied on components $1 \dots k-1$), they are *incomparable* at component $k$—neither strictly ordered nor a full-key tie. If any incomparable pair on the surviving frontier $F_{k-1}$ immediately halts Stage 2 with `INCONCLUSIVE`, injecting a single uncharacterized (`UNKNOWN`) candidate into $C$ acts as a trivial denial-of-selection (poison-pill) vector. (ii) If candidate $c_3 \in F_{k-1}$ strictly dominates both $c_1$ and $c_2$ at an earlier component $j < k$, step-by-step frontier reduction $F_j = \min(F_{j-1})$ must prune $c_1$ and $c_2$ before component $k$ is reached so their incomparability at $k$ becomes non-decision-affecting. (iii) Since $\Delta W_{\text{worst}}(c)$ in logical `U` is a *"declared worst-case logical work bound under $W$ (not runtime sample or Joules)"*, `boc.md` §8 should specify when `MEASURED` is ever valid for $\Delta W_{\text{worst}}(c)$ (e.g., exhaustive deterministic execution over a finite/singleton workload domain $W$) and whether integer `U` bounds bearing `MEASURED` and `FORMALLY_DERIVED` modalities are directly comparable.
     4. **Crash-Recovery Budget Reservation Idempotency (§2.2, p. 9; §2.3, p. 11):** Section 2.3 (`boc.md` §10, p. 11) defines an execution lifecycle (`PREPARED`, `RUNNING`, `PAUSED`, `COMPLETED`, `ABORTED`) with *"atomic operation checkpoints, pre-operation budget reservation, idempotent recovery."* If an invocation crashes or pauses after deducting $W_{\text{gate}} > 0$ or a pre-operation candidate evaluation budget reservation $\Delta B_i$ from $B$ but before committing the post-operation checkpoint, a naive replay from the prior checkpoint will deduct $\Delta B_i$ or $W_{\text{gate}}$ a second time, violating idempotency and causing premature `BUDGET_EXHAUSTED` termination. `boc.md` §10 should specify that pre-operation budget reservations and gateway deductions are persisted atomically inside the checkpoint escrow state bound to a deterministic operation idempotency key $\text{op\_id} = H(\text{invocation\_id} \mathbin{\|} \text{candidate\_id} \mathbin{\|} \text{stage\_step})$, so recovery reuses the active escrow reservation rather than re-debiting $B$.

2. **RFC 8785 (JCS) IEEE-754 Numeric Canonicalization vs. Operational Axiom 10 (No IEEE 754 Floating-Point) in BOC Receipts (§2.3, p. 11 vs. §3.3, pp. 14–15)**
   - **Potential Concern:** Section 2.3 (`boc.md` §9, p. 11) specifies that BOC decision receipts undergo deterministic canonicalization via **RFC 8785 JSON Canonicalization Scheme (JCS)** over UTF-8. Standard RFC 8785 (§3.2.2.3) mandates serializing all native JSON number tokens by converting them to IEEE 754 double-precision floats (`binary64`) and applying ECMAScript number-to-string formatting rules. However, Operational Axiom 10 (`qnPrimitive.md` §3.3, pp. 14–15) strictly prohibits IEEE 754 floating-point representations across the architecture, and Qn/QnIR logical work bounds ($\Delta W_{\text{worst}}(c)$), budgets ($B$), or 64-bit/unbounded cycle counters ($\tau_t$) can exceed the $2^{53} - 1$ exact integer precision ceiling of IEEE 754 `binary64`. Serializing such fields as native JSON numbers under RFC 8785 would silently coerce them through IEEE 754 `binary64` formatting and lose low-order bits above $2^{53} - 1$.
   - **Recommended Resolution:** Explicitly stipulate in `boc.md` §9 (and summarize in §2.3, p. 11) that within the `CDQN-BOC-RECEIPT-v1` JSON schema, all 64-bit or arbitrary-precision integer work bounds, budgets, cycle counts, and $\langle z, r, d \rangle$ zoom quantities must be serialized as canonical base-10 ASCII strings (or hex-encoded byte strings) prior to RFC 8785 JCS canonicalization, restricting any native JSON integer literals strictly to small bounded metadata tags in $[0, 2^{53}-1]$ to maintain full compliance with Axiom 10.

3. **Cross-Layer Notation and Boundary Mismatch in the Two-Axis Consequentiality Constraint (§2.2, p. 9 vs. §3.3, p. 15 & §4.1, p. 16)**
   - **Potential Concern:** In §2.2 (p. 9), the Consequentiality Constraint (`simemp.md` §4) states that *"Memory-locality optimizations (`Q(reuse)`/`Q(bypass)`) are admissible only when advantage over direct compute is declared on both work ($\kappa_{\text{dcc}} \ge 1$) and latency ($\kappa_t \ge 1$) axes."* Comparing this formulation against §3.3 (`qnPrimitive.md` v1.4.0, p. 15) and §4.1 (`qexpr.md` v1.4.0, p. 16) reveals three discrepancies:
     1. **Parameter Domain vs. Advantage Ratio Conflation:** $\kappa_{\text{dcc}}, \kappa_t \in [1, 64]$ (with recommended presets $\kappa_{\text{dcc}} = 2, \kappa_t = 4$) are the BOC-adjudicated *margin multiplier parameters*, whereas the realized static compute-to-lookup advantage ratios are $\frac{\Delta W_{\text{compute}}}{\tau_U[\text{tier}(h)] + \varepsilon_U}$ and $\frac{\Delta t_{\text{compute\_bound}}}{\tau_t[\text{tier}(h)] + \varepsilon_t}$.
     2. **Weak Inequality ($\ge$) vs. Strict Inequality ($>$) on Boundary Ties:** Writing $(\kappa_{\text{dcc}} \ge 1)$ and $(\kappa_t \ge 1)$ in §2.2 suggests weak inequality is sufficient at parity ($\kappa = 1, \varepsilon = 0$), whereas the formal `Q(reuse)` predicate in §3.3 (`qnPrimitive.md` §1.15/§5.9, p. 15) requires **strict** inequality on both axes ($\Delta W_{\text{compute}} > \kappa_{\text{dcc}} \cdot (\tau_U[\text{tier}(h)] + \varepsilon_U)$ and $\Delta t_{\text{compute\_bound}} > \kappa_t \cdot (\tau_t[\text{tier}(h)] + \varepsilon_t)$) and explicitly mandates that *"ties resolve to Direct Compute."*
     3. **Compile-Time `Q(bypass)` vs. Runtime Tier Lookup `Q(reuse)`:** In §4.1 (`qexpr.md` v1.4.0, p. 16), `Q(bypass)` (`OP_BYPASS`) is a fixed 16-rule compile-time symbolic contraction suite ($\Delta W = 0$) confined strictly to reversible symbolic evolution *outside* memory-tier traversal, whereas runtime tier-lookup bounds $(\tau_U[\text{tier}(h)], \tau_t[\text{tier}(h)])$ govern `Q(reuse)`.
   - **Recommended Resolution:** Align §2.2 (`simemp.md` §4) with `qnPrimitive.md` v1.4.0 and `qexpr.md` v1.4.0 by scoping the runtime two-axis tier-lookup inequality specifically to `Q(reuse)` (while cross-referencing `Q(bypass)` to compile-time zero-work contraction) and stating that static compute bounds must *strictly exceed* the margin-scaled lookup bounds for $\kappa_{\text{dcc}}, \kappa_t \ge 1$, with ties resolving to Direct Compute.

4. **Missing Origin-Quotiented Projection ($H_{\text{pub}}$) and DCC Profile Binding in the Observational Determinism Invariant (§2.1, pp. 7–8 vs. §3.1, p. 13 & §3.3, p. 14)**
   - **Potential Concern:** In §2.1 (pp. 7–8), the `CANDIDATE` Observational Determinism Invariant states that for any two Layer-0 environments $E_1, E_2$ agreeing on declared dependency projections ($\Pi_{\mathcal{D}}(E_1) = \Pi_{\mathcal{D}}(E_2)$) and satisfying the active DCC hardware profile, evaluating a governed transition yields bit-identical output commitments $H(S_t(E_1)) = H(S_t(E_2))$ and identical terminal receipt statuses. Two cross-layer dependencies must be explicitly bound for this invariant to hold:
     1. **Origin Quotienting:** Under Operational Axiom 4 (`qnPrimitive.md` §3.3, p. 14), every governed state carries its local node genesis identity $Q(0)_N \in \text{Lineage}(\alpha)$ inside its 9-block Universal Envelope. Across two distinct physical Layer-0 nodes $E_1$ and $E_2$, $Q(0)_{E_1} \neq Q(0)_{E_2}$, so raw envelope hashes $H(S_t(E_1))$ and $H(S_t(E_2))$ will differ unless hashed through the **Origin-Quotiented Canonical Projection** $H_{\text{pub}}$ ($Q(0)_A \mapsto \hat{Q}(0)$, defined in §3.1, p. 13).
     2. **Committed DCC Profile Tables vs. Node-Local Calibration:** Because Layer-0 hardware telemetry (§2.2, pp. 8–9) binds to `U` via node-local Historical Calibration Benchmark receipts, if $E_1$ and $E_2$ evaluated `Q(reuse)` admission against their own node-local calibration tables $\tau_U^{(1)} \neq \tau_U^{(2)}$ or $\tau_t^{(1)} \neq \tau_t^{(2)}$ rather than the shared static bound tables declared in the active DCC profile contract $P \in \mathcal{D}(S_t)$, one node could admit a lookup while the other falls back to Direct Compute, diverging in logical work charges $\text{Work}(E)$ and terminal budget statuses.
   - **Recommended Resolution:** Replace $H(S_t(E_1)) = H(S_t(E_2))$ in `simemp.md` §2.1 with the origin-quotiented commitment $H_{\text{pub}}(S_t(E_1)) = H_{\text{pub}}(S_t(E_2))$, and explicitly state that the shared DCC profile's static bound tables $(\tau_U, \tau_t)$ are fixed inside $\Pi_{\mathcal{D}}(E)$ (whereas node-local calibration receipts are used solely at Stage 1 to verify that physical nodes $E_1$ and $E_2$ qualify to satisfy the active DCC profile).

5. **Boundary Ambiguity Between the Protocol-Blind Payload Safe Harbor and Commercial Scaling Volume Thresholds (§2.4, p. 11)**
   - **Potential Concern:** Section 2.4 (`LICENSE.md` §1.5 / `index.md` §5, p. 11) defines five disjunctive commercial scaling triggers (annual gross revenue $> \$1{,}000{,}000\text{ USD}$, capital raised / enterprise valuation / AUM $> \$5{,}000{,}000\text{ USD}$, $> 10{,}000$ active instances/agents, $> 100{,}000\text{ MAU}$, or $> 10{,}000{,}000$ monthly transactions), immediately followed by the exemption: *"Sovereign user `Payloads` sit behind a protocol-blind safe-harbor air gap and do not trigger scaling usage by mere wrapping/settlement."* Because Outer-Ring `cdqn` nodes operate exclusively over origin-quotiented commitments $H_{\text{pub}}$ and opaque `PayloadRef` digests (Axiom 3, p. 14; §3.1, p. 12), a commercial operator running a high-volume settlement hub ($> 10{,}000{,}000$ monthly transactions or $> 100{,}000\text{ MAU}$) could argue that all processed transactions constitute "mere wrapping/settlement" of opaque sovereign user `Payloads` and are therefore exempt from the commercial scaling thresholds.
   - **Recommended Resolution:** Clarify in `LICENSE.md` §1.5 and `index.md` §5 (summarized in §2.4, p. 11) that the Safe-Harbor Air Gap protects *sovereign payload authors/end-users* from having their private payload contents or downstream business metrics counted as commercial scaling of the Qn core by mere envelope wrapping/settlement, whereas *infrastructure/hub operators* executing Qn/cdqn gateway, routing, or settlement services remain subject to the instance, MAU, and monthly transaction thresholds across the envelopes they process regardless of payload opacity.

### [Execution Core (Layers 0–3), Category A/B Primitives, Orthogonal Domain Lattice & Vision/Governance Proposals] (Pages: 11-21)
#### Potential Mistakes and Improvements

1. **Cross-Layer Terminal Status Discrepancy Between Axiom 6 (Sealed 12-Status Registry), `Q(reuse)` Fault Handling, and `QnIR` v0.3 Terminal Outcomes (§3.1, §3.3, §4.2, §6.2, §6.6)**
   * **Location:** Section 3.1 (`abstractionLayers.md` v1.9.1 §3.6, p. 12), Section 3.3 (`qnPrimitive.md` v1.4.0 Axiom 6 & §5.9, pp. 14–15), and Section 4.2 (`qm.md` v1.4.0, p. 17), in relation to Section 6.2 (`qnir_semantics.md` §2.5, pp. 24–25) and Section 6.6 (`qnir_commitments.md` §6.7, p. 27).
   * **Potential Concern:** Section 3.1 and Section 3.3 (Axiom 6: *Totality of Governed Operations*) establish a **Sealed 12-Status Terminal Registry** governing all operations:
     $$\texttt{SUCCESS}, \texttt{FAILURE}, \texttt{NO\_SOLUTION}, \texttt{TIMEOUT}, \texttt{BUDGET\_EXHAUSTED}, \texttt{INCONCLUSIVE}, \texttt{QUARANTINED},$$
     $$\texttt{PRECISION\_INSUFFICIENT}, \texttt{EXPRESSION\_TOO\_COMPLEX}, \texttt{REJECTION\_BY\_GATEWAY},$$
     $$\texttt{DIVISION\_BY\_ZERO\_REJECTED}, \texttt{ORDERING\_INDETERMINATE\_AT\_ZOOM}.$$
     Tracing these terminal statuses across the primitive, domain, and execution specifications reveals four cross-layer alignment gaps that directly affect the `R11'` source-to-target simulation relation (`Qexpr` $\to$ `QnIR`) and outer receipt lifting:
     1. *Unregistered `HALTED` Status in `qnPrimitive.md` (§3.3, p. 15):* Under the *4-Field Admission Ledger*, the specification states: *"Faulted lookup emits `HALTED` with no charge beyond gateway fee."* However, `HALTED` is not a member of the Sealed 12-Status Terminal Registry in Axiom 6 (whereas in `qnir_semantics.md` §2.2, p. 22, `halted(outcome)` is an internal machine configuration state wrapper rather than a terminal outcome symbol, and lookup misses birth a Tier-O `STATUS_LOOKUP_MISS` token routed to a fallback basic block).
     2. *Unmapped Domain Sub-Code `FRAME_SIGNATURE_INSUFFICIENT` in `qm.md` (§4.2, p. 17):* Under *Even Roots & Negative Rationals*, $n \ge Q(4)$ even negative roots require mixed-grade spinors (Degree 2) or `FRAME_SIGNATURE_INSUFFICIENT`, whereas `ERR_KAPPA_UNDECLARED` is explicitly wrapped in `REJECTION_BY_GATEWAY` (`REJECTION_BY_GATEWAY (ERR_KAPPA_UNDECLARED)`). #### Potential Mistakes and Improvements

1. **Exact Equality Claim for the Static Admission Surrogate $\hat{B}(P) = B(P)$ vs. Semantic Feasibility, Reducibility, and Unrolled DP State-Space Blowup (§1.1 `draft.22`, p. 4; §6.4, p. 26):**
   - **Potential Concern:** In §1.1 (`draft.22`, p. 4) and §6.4 (p. 26), retiring the depth ceiling (`F26`, Option B) is stated to strengthen the §3.4 static admission surrogate from an inequality $\hat{B}(P) \ge B(P)$ to "exact equality `B_hat(P) = B(P)` identically for all well-formed Intents," computed via a topological dynamic program (DP) over the unrolled acyclic state graph `(block_id, remaining_trip_vector)` in $\mathcal{O}(|B|\prod_i(\text{ceil}_i+1)\cdot d)$ time and space. Four technical issues arise from this formulation:
     1. *Syntactic Graph Supremum vs. Semantically Realizable Supremum:* Removing the separate depth ceiling eliminates the artificial path truncation that previously caused $\hat{B}(P)$ to diverge from the maximum-weight walk on the uninterpreted control-flow graph (CFG). However, a purely topological DP over `(block_id, remaining_trip_vector)` is path-insensitive with respect to concrete data values, conditional branch predicates (`CMP`/`OBS` condition codes `cc` in `BR`), store contents (`D[addr]` hits vs. misses in `CLOAD`), early loop exits via `HALT`, and mid-block `0`-charge fatal rejections (e.g., operand/result bound violations on `CONST`, `CLOAD` hit, `TUPLE`, `ADD`/`SUB`/`MUL`, `CMP` range, or `DIV`/`MOD` by zero, which immediately invoke fatal terminalization `T` per §6.2, p. 24 and §6.4, p. 25). If $B(P)$ denotes the *semantically realizable* worst-case execution work $\sup_{D} \text{Work}(\text{Eval}(P, D, V))$, then any Intent with mutually exclusive branch predicates, correlated `CLOAD` outcomes, or unavoidable mid-block rejections can have a heaviest syntactic walk that is dynamically unreachable across all valid stores $D$, yielding $\hat{B}(P) > B_{\text{sem}}(P)$.
     2. *Reducibility and Feedback Arc Set Verification (`F26`, `draft.22`, p. 4):* In directed graph theory, the premise that *"every block-graph cycle contains a back-edge with a finite trip ceiling"* holds unambiguously across irreducible multi-entry loops only if static well-formedness verifies that removing all trip-ceiling-annotated edges (`BR`, `JMP`, and `CLOAD` miss fallback edges) leaves a strict DAG, or enforces a topological block-index ordering invariant.
     3. *Exponential State-Space Denial-of-Service at Admission:* Because the unrolled state space scales with the *Cartesian product* $\prod_{i=1}^k (\text{ceil}_i + 1)$ across all $k$ back-edges (including `BR`, `JMP`, and `CLOAD` miss fallback back-edges per `F25`), an Intent with even a small number of sequential or independent loops (e.g., $k = 10$ back-edges each with $\text{ceil}_i = 15$) generates $\prod_i (\text{ceil}_i + 1) = 16^{10} \approx 1.1 \times 10^{12}$ DP states prior to executing transition 1.
