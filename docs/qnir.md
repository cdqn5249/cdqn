## Status and Program of Record

This file is the working draft of {% include term.html id="qnir" text="QnIR" %} v0.3 — the intermediate-representation layer of the Qn definition taxonomy, positioned between the {% include term.html id="qnlang" text="QnLang" %} surface language (whose expressions collapse deterministically to concrete values at compilation time, `docs/abstractionLayers.md` §6.3) and the execution substrate. The layer's declared role is fixed by the committed glossary definition of `docs/_data/glossary/primitives.yml` and is unchanged by this draft: intermediate representation for hardware abstraction, bound enforcement, and deterministic execution without exposing floating-point semantics. The file status is **DRAFT**: QnIR remains **[PENDING]** in the portal milestone diagram (`docs/index.md`), and canon entry is gated exclusively by the promotion criterion quoted below. Every artifact in this file carries the tag **[v0.3.0-draft.5 — DRAFT]** for new declarations, with the committed declarations of v0.3.0-draft.1 through v0.3.0-draft.4 standing as committed except where a Loop-3 repair wave explicitly withdraws a wording (each withdrawal itemized, with the withdrawn bytes preserved verbatim, in the Wave record of the wave that made it) and the claimed validity of the record is internal consistency within declared finite boundaries under {% include term.html id="computational-consistency" %}.

The governing instrument of the entire draft is the Loop-2 adversarial review of the QnIR v0.2 candidate (verdict preserved verbatim: "major revision; do not promote QnIR v0.2 to the canon"), whose required repair sequence is preserved verbatim below. The sequence's own preamble — "The order matters because later artifacts inherit earlier definitions." — and the review's milestone framing are preserved verbatim from the scope-and-verdict section:

> The appropriate v0.3 milestone is therefore a small, executable core with a formal transition relation and differential tests. Geometric products, containers, calls, fork–join, and STARK proving should remain profile-gated extensions until each has a specified state transition, cost bound, and validator. The draft's narrow "no implementation, no superiority, no closure" disclaimer is accurate and should remain.

**Required v0.3 repair sequence** (preserved verbatim from [`docs/AiReviews/AiReviewQnIRv0.2.md`](https://github.com/cdqn5249/cdqn/blob/main/docs/AiReviews/AiReviewQnIRv0.2.md) §5):

| Step | Action | Acceptance condition |
|---|---|---|
| 1 | Freeze a minimal core | Constants, tuples, exact arithmetic, comparison, bounded structured control, status, commit, witness, and halt. Move calls, saturation, containers, fork–join, and road proofs to extensions. |
| 2 | Publish operational semantics | Typed configurations, small-step transitions, block arguments, dynamic instances, token lifecycle, failure behavior, and deterministic encodings. State determinism as `Eval(Intent, D, V) = Execution` with all semantic versions explicit. |
| 3 | Repair work accounting | One ledger equation; static operand bounds; sound control-flow budget admission; reserve/charge/refund invariants; no double billing. |
| 4 | Build a conformance oracle | Assembler, validator, interpreter, and independent second implementation. Re-encode all examples and add adversarial tests for loops, calls, collisions, unresolved statuses, and budget boundaries. |
| 5 | Strengthen commitments | Full-transition trace roots, collision-safe artifact comparison, normative lineage, and versioned verbalizer/extractor identities. |
| 6 | Add extensions with evidence | Container BOC, call trade study, liveness histograms, choreographic refinement, then class-specific AIRs and measured Realization A/B break-even. |

**Promotion criterion** (preserved verbatim from the same section):

> v0.3 may enter the canon only when the core semantics and ledger pass independent differential execution, every normative example validates, and each retained extension has an explicit proof or measurement artifact. Until then, "Candidate 1" must not be called Theorem 1, and `R11'`, `R12'`, `R19`, and the `O(polylog)` verification statement must remain conditional.

Three named bans therefore govern every increment of this draft, and each is inherited unchanged from the review: (i) no claim artifact of the v0.3 program is styled as a theorem — construct claims remain *Candidates* until the promotion criterion is met; (ii) `R11'` remains a *defined compilation relation to be demonstrated* by forward (and where intended, backward) simulation over typed source and target semantics, never an isomorphism claim (finding F8); (iii) `R12'`, `R19`, and the `O(polylog)` verification statement remain conditional, profile-gated hypothesis text until their respective proof or measurement artifacts exist. Deterministic execution under {% include term.html id="dependencies-determinism" %} is the design objective of Steps 2–4, not an established property of this draft.
